## 1. 研究动机与背景

化工安全事故具有"小概率、大后果"的特征——单起事故可能导致数百人伤亡和数亿元损失。然而，事故调查报告分散在政府网站、行业数据库和学术文献中，以非结构化文本形式存在，难以被系统性地查询和分析。

传统的事故分析方法依赖人工阅读报告、手动归纳模式，效率低下且难以扩展到大规模数据。大型语言模型（LLM）虽然在文本理解和生成方面展现出强大能力，但在专业领域中存在幻觉问题——模型可能编造不存在的事故原因或混淆不同事故的细节。

本项目的核心动机是：**能否利用 LLM 自动从海量非结构化事故报告中构建结构化知识图谱，再用图谱中的因果约束来回答安全问题，同时控制幻觉？**

### 1.1 相关工作

传统化工事故数据库（如 eMARS、CSB）提供事故记录但缺乏因果链建模和自动化抽取。现有 Graph RAG 研究多聚焦通用领域，缺乏针对化工安全这一高风险垂直领域的定制化 Prompt 策略和幻觉控制实验。本项目填补了这一空白：提出领域特定的 Prompt Chain + 通过三组对照实验量化验证 Graph RAG 的幻觉控制效果。

## 2. 问题定义与挑战

### 核心问题

1. **自动化 KG 构建**：如何从 1,300+ 份非结构化中文化工事故报告中，自动抽取实体、关系与因果链？
2. **因果约束问答**：如何在回答安全问题时，确保每个陈述都能追溯到知识图谱中的因果路径，从而控制幻觉？
3. **多源数据融合**：如何将事故报告、化学品物性、气象数据等多个异构数据源整合为统一的分析视图？

### 关键挑战

- **中文事故文本的特殊性**：化工事故报告使用大量专业术语和长句描述，实体边界模糊
- **因果链完整性**：单起事故的因果链可能涉及 5–10 步，LLM 容易遗漏中间环节或添加推测
- **幻觉控制**：纯 LLM 回答专业安全问题时平均产生 13.2 个不在知识图谱中的实体
- **数据源碎片化**：事故数据分散在多个政府网站和公众号中，格式各异

## 3. 解决方法

### 3.1 系统架构

系统采用五层架构设计，数据流从下往上单向传递：

1. **数据获取与预处理层**：爬虫采集 mem.gov.cn 月度汇编、微信 JSON 预处理、PubChem API 调用
2. **LLM 知识抽取层**：Prompt Chain 策略驱动 DeepSeek v4-flash 抽取实体与因果链
3. **知识存储层**：Neo4j 5.26 图数据库（因果链）+ SQLite 关系数据库（结构化记录），跨源链接器同步
4. **Graph RAG 检索层**：三层实体匹配（精确/关键词/嵌入语义）→ Cypher 因果路径查询
5. **前端应用层**：Streamlit 5 页面 Web 应用（概览/问答/分析/图谱/管理）

### 3.2 LLM 驱动的知识抽取（核心创新一）

采用 Prompt Chain 策略驱动 DeepSeek deepseek-v4-flash：
- **5 种实体类型**：Equipment、Material、Abnormal_Condition、Consequence、Mitigation
- **3 种关系类型**：leads_to、involves、mitigated_by
- **JSON 3 级容错恢复**：空响应重试 → 自动修复常见错误 → 正则提取

详细 Prompt 设计见 `src/extraction/prompt_templates.py`。v0.7 最终版本含 8 条精炼规则 + 4 组常见错误反例 + 完整 Few-shot 示例。实际抽取成功率 99%+（1,579 段成功 / ~1,600 段总尝试）。

### 3.3 Graph RAG 因果约束问答（核心创新二）

### 3.3 Graph RAG 因果约束问答（核心创新二）

三层实体匹配策略：L1 精确匹配（置信度 0.6–1.0，权重×3）、L2 jieba 关键词命中（命中数加权，权重×1）、L3 sentence-transformers 嵌入语义匹配（自适应阈值，权重×3）。融合后加路径奖励（有出边的实体+2 分）。

匹配后通过 Cypher 变长路径查询 `()-[*0..4]->()` 检索因果链，去重与子路径过滤后格式化为 LLM 可读上下文。生成答案时系统 Prompt 有六条约束，核心三条：严格按路径回答、路径为空诚实拒答、每条陈述标注[路径N]来源。

### 3.4 双存储与跨源链接

### 3.4 双存储与跨源链接

Neo4j 存因果链，设备/物料名设 UNIQUE 约束防重复，AlNeormal_Condition 建普通索引。SQLite 用 SQLAlchemy ORM 管理事故记录表、化学品物性表、气象记录表，建 4 个索引和 1 个分析视图。DataLinker 做双向属性同步和一致性校验（节点覆盖率、孤立节点检测）。

## 4. 数据流水线

### 4.1 数据采集

### 4.1 数据采集

mem.gov.cn 全量 95 个月度汇编页，BeautifulSoup 解析 HTML，正则提取每起事故的标题/日期/来源/正文，保存为 UTF-8 文本文件（1,261 份）。微信公众号 JSON 数据集经筛选保留 108 篇事故详情，文本清洗去除微信噪声后保存 74 篇（Mitigation 主要来源）。PubChem 29 种危化品物性通过 pubchempy 获取。

### 4.2 预处理

### 4.2 预处理

文本清洗包括空白规范化、标点标准化、PII 脱敏。mem 文件用 frontmatter 格式（标题/来源/日期/=====/正文），微信文件用标题/摘要/=====/正文格式。数据融合通过 DataMerger 实现事故↔化学品关联（文本提取+标准化映射）和事故↔气象关联（时空最近匹配）。

### 4.3 知识抽取

### 4.3 知识抽取

`scripts/rebuild_all.py` 提供完整的重建链路：清空数据库 → 爬虫 → 微信预处理 → LLM 批量抽取（Phase 1 并发 200 线程 + Phase 2 串行写入）→ 化学品充实 → 验证。支持断点续跑（`continue_extraction.py`）。每次抽取同时写入 Neo4j（三元组，事务批量）和 SQLite（事故记录，逐条）。

### 4.4 存储与索引

### 4.4 存储与索引

Neo4j 约束：Equipment.name UNIQUE、Material.name UNIQUE、Accident.title UNIQUE。索引：Abnormal_Condition.name、Accident.id。SQLite ORM 模型定义在 `src/storage/relational_db.py`（AccidentRecord、ChemicalProperty、WeatherRecord）。嵌入缓存使用 `entity_embeddings.npz`，支持增量更新——实体列表未变更时跳过重建。

### 4.5 检索与问答

### 4.5 检索与问答

Cypher 查询以目标实体为中心双向扩展（`*0..max_depth`），经 `leads_to|involves|mitigated_by` 路径，按长度降序返回。`CausalPathRetriever.format_context()` 将查询结果格式化为含实体类型标签的结构化文本。`AnswerGenerator` 调用 LLM 在 Graph RAG 系统 Prompt 约束下生成答案，失败时降级返回原始路径。

### 4.6 可视化与分析

### 4.6 可视化与分析

Streamlit 5 页面应用（暗色主题 + 青色强调色）：系统概览（6 度量卡片 + 架构图）、因果推理问答（推荐问题 + 实体匹配预览 + 回答强调框）、多维数据分析（4 标签页 × 6+ 种 Plotly 图表）、知识图谱浏览（streamlit-agraph 交互图 + 因果路径探索）、系统管理（流水线指南 + 配置检查）。

## 5. 实验分析

### 5.1 数据规模

| 指标 | 数值 |
|------|------|
| 知识图谱节点 | 6,976（Abnormal 3,570 / Accident 1,579 / Equipment 688 / Consequence 641 / Material 427 / Mitigation 71） |
| 因果关系边 | 23,111 |
| SQLite 事故记录 | 1,579（100%含根原因与后果，79%含日期） |
| 化学品物性 | 29 种 |
| 时间跨度 | 1947–2026（79 年） |

### 5.2 对照实验：Graph RAG vs 关键词RAG vs 纯LLM

20 组问题覆盖 7 种因果模式，三组 baseline 同时对比。核心结果：

| 指标 | 关键词RAG | Graph RAG | 纯LLM |
|------|----------|-----------|--------|
| 无幻觉率 | 40% | **70%** | 5% |
| 来源可追溯率 | 100% | 55% | 0% |
| 诚实拒答率 | 10% | **55%** | 0% |
| 平均幻觉实体数 | 1.2 | **0.65** | 5.95 |

### 5.3 幻觉检测方法

从 Neo4j 导出完整实体名白名单，结合化工安全领域特征词正则提取回答中的候选实体，逐一比对白名单。不在 KG 中的实体标记为幻觉。

### 5.4 数据洞察

事故类型：爆炸占 61.2%，中毒窒息 26.9%，火灾 5.1%。时间趋势：2010 年代为高峰（616 起），2020 年代显著下降。化学品频次 Top 3：硫化氢 49 起、氮气 43 起、甲醇 39 起。设备频次 Top 1：反应釜 62 起。最危险异常状态："形成爆炸性混合气体"关联 102 个后果节点。因果链以 2-3 步级联为主，最深可达 6 步。

## 7. 经验与教训

### Prompt 工程的迭代本质
Prompt Chain 策略从最初的 6 条基础规则逐步迭代到 8 条精细规则。每次迭代的驱动因素都是实际抽取结果中的模式性错误：实体名过长（"操作人员未佩戴防护用品情况下盲目进入有限空间施救"）→ 事件原子化规则；提取结果中人员与设备混在一起（"操作工误开阀门"作为一个 entity）→ 人员操作分离规则；Abnormal_Condition 占比 67.5% → Equipment/Material 优先识别规则。每条规则背后是几十条失败案例的归纳。

### 双存储的必要性
最初我们担心 Neo4j + SQLite 双存储会是过度设计。实际使用中发现，图数据库对因果路径查询天然匹配（"A 导致 B"即是有向边），而关系数据库对统计聚合（GROUP BY、COUNT、JOIN）更高效。两者各司其职的设计最后被证明是最自然的。

### JSON 截断问题排查
早期 max_tokens=4096 时，LLM 输出的 JSON 频繁在半截截断——因为一条完整因果链的 JSON 可达 3,000+ tokens，加上 Prompt 的 800 tokens，4,096 刚好不够。从 4096 → 8192 → 16384 的逐级调整才彻底解决。

### 分类器设计的教训
`_classify_and_split` 函数最初为微信文章设计，但被对所有文件通用调用。两次误杀 mem 文件（length<200 阈值、acc_kw<5 阈值）都是因为假设了输入为微信长文。最终通过添加 `is_wechat` 判断将 mem 文件排除在分类器之外。

### 实验先行的价值
如果在项目初期就建立对照实验框架，很多优化方向会有数据支撑而不是凭感觉。三组 baseline 的对比实验是后期才完善的——如果能更早引入，Prompt 迭代的方向会更加明确。

## 8. 项目总结

ChemSafe-KG 构建了首个大规模结构化中文化工安全事故知识图谱。通过 LLM 驱动的 Prompt Chain 策略，从 1,579 份非结构化报告中自动抽取了 6,976 个实体和 23,111 条因果关系，并实现了基于因果路径约束的 Graph RAG 问答系统。

对照实验证明：相比纯 LLM，Graph RAG 将幻觉实体数减少 9 倍（0.65 vs 5.95），来源可追溯率达 55%（纯 LLM 为 0%），并且在知识图谱覆盖范围外的问题上诚实拒答率 55%（纯 LLM 为 0%）。

本项目验证了"用 LLM 建 KG，再用 KG 约束 LLM"这一闭环方法在化工安全领域的可行性和有效性。
