# ChemSafe-KG 图谱探索报告

> 从现状出发，探索知识图谱在化工安全领域的真正潜力，以及实现路径。


## 当前状态与理想状态的差距

**当前图谱**：基于 150 字月度简报的碎片化因果链。6,976 节点但大量同义未消歧，链平均深度 1-2 跳。能回答"某起事故中 A 导致 B"这类单链问题，但无法回答跨事故模式问题。

**理想图谱**：基于详细调查报告的多层次因果网络。实体消歧后节点数降但连通性升，链深度 5+ 跳，能支持跨事故模式挖掘、失效树分析、风险传导路径建模。


## KG 可以做但当前没做到的六件事

### 1. 跨事故因果模式挖掘

**当前状态**：只能回答"某起事故中发生了什么"。无法回答"在所有爆炸事故中，最常见的触发条件是什么"。

**KG 能做**：一旦实体消歧，同一类异常状态（如"温度超限"）在不同事故中会合并为同一节点。此时查询"温度超限→?→爆炸"就能返回所有事故中共享的因果模式，按频次排序。

```
MATCH path = (cause:Abnormal_Condition)-[:leads_to*1..4]->(effect:Consequence)
WHERE cause.name CONTAINS '温度' AND effect.name CONTAINS '爆炸'
RETURN cause.name, effect.name, count(*) AS freq, collect(DISTINCT accident_id)
ORDER BY freq DESC
```

**实现路径**：实体消歧（优先级 P0）。同义节点合并后，这类查询立即生效。

### 2. 失效树分析

**当前状态**：图谱是碎片化的线性链，没有分叉汇聚结构。

**KG 能做**：从后果反向追溯所有可能的原因路径，构建类似故障树的 DAG 结构。用户问"储罐爆炸可能由哪些原因导致"，返回的不是一条链，而是一棵具有多条分支的因果树。

**实现路径**：引入反向关系（`caused_by`），在抽取 Prompt 中增加"同时标注后果的多种可能原因"的指令。

### 3. 风险传导路径建模

**当前状态**：设备和化学品作为孤立节点，没有"风险沿设备链传导"的概念。

**KG 能做**：建模"反应釜温度失控→管道压力升高→阀门失效→物料泄漏→火灾"这种跨设备的传导链。每个设备节点标注其承受的极限条件（温度/压力/腐蚀性），当因果链途经该设备时，可以判断是否超出安全阈值。

**实现路径**：Schema 扩展——为 Equipment 节点增加属性（max_temp, max_pressure, material），为 leads_to 关系增加属性（probability, severity, time_lag）。

### 4. 化学品危险性知识库

**当前状态**：化学品物性存在 SQLite 中，与因果链不关联。

**KG 能做**：当因果链涉及某种化学品时，自动关联其闪点、爆炸极限、毒性分类。回答"涉及低闪点化学品的爆炸事故，平均因果链长度是否更长"这类需要物性+因果的联合查询。

**实现路径**：将 chemical_properties 导入 Neo4j 作为 Material 节点的属性，或建立 `has_property` 关系。

### 5. 措施效果评估

**当前状态**：Mitigation 节点只有 71 个，且与事故的因果链不关联。

**KG 能做**：标注每条因果链上是否有 Mitigation 节点。统计"有应急措施的同类事故，后果严重程度是否显著低于无措施的事故"。如果数据支持，可以给出量化的措施效果评估。

**实现路径**：扩大 Mitigation 数据源（CSB 报告每份含 5-20 条 safety recommendations）。在因果链上明确标注 mitigated_by 断点位置。

### 6. 时间序列因果推理

**当前状态**：所有关系都是静态的 leads_to，没有时间维度。

**KG 能做**：为每条 leads_to 关系标注时间间隔（秒/分钟/小时）。回答"从温度异常到爆炸，典型的时间窗是多长"——这对应急响应有直接操作意义。

**实现路径**：在抽取 Prompt 中增加"提取事件之间的时间间隔"指令。关系属性增加 `time_interval` 和 `time_unit`。


## 从当前到理想的三步路线图

```
Phase 1 (可立即执行) ────────────────────
  □ 实体消歧: 合并同义 Abnormal_Condition 节点
    预期: 节点数降 20-30%, 连通性升 40%+
  □ 导入化学品物性到 Neo4j Material 节点
  □ 事故去重 (已完成: 405条标记)
  
Phase 2 (需新数据源) ────────────────────
  □ 接入 CSB 英文调查报告 (数万字/份)
    预期: Mitigation 71→200+, 因果链深度 1-2跳→5+跳
  □ Schema 扩展: 关系属性(severity, time), 反向关系(caused_by)
  □ 关系类型扩展: triggers, prevents, requires, depends_on
  
Phase 3 (分析能力) ────────────────────
  □ 跨事故模式挖掘: 最高频因果链 Top N
  □ 失效树自动构建: 从后果反向追溯
  □ 措施效果评估: 有/无 mitigation 的事故后果对比
  □ 风险预测模型: 基于历史数据训练设备故障概率
```


## 一个具体案例

**当前能回答的**：
> Q: 硫化氢溢出会造成什么危害？
> A: [路径3] 硫化氢溢出 → 人员中毒死亡

**消歧和扩展后能回答的**：
> Q: 在所有中毒事故中，硫化氢涉及的比例是多少？最常见的泄漏源是什么设备？
> A: 硫化氢涉及 43% 的中毒事故（342起中的147起）。最常见的泄漏源是管道腐蚀（31%）和储罐阀门失效（24%）。硫化氢中毒事故中，75% 发生在有限空间。平均从事发到伤亡的时间窗为 3-8 分钟，意味着应急响应几乎不可能赶在伤亡前完成——预防比应急更重要。


## 结论

当前 KG 的限制不是 KG 本身的问题，是数据输入质量的问题。用 150 字简报建的图，相当于用沙子砌墙。同样的架构和 Prompt Chain，换上 CSB 级别的数据源，加上实体消歧和 Schema 扩展，KG 可以实现六种当前做不到的分析能力。我们项目的价值不是"证明了 KG 不行"，而是"锁定了让 KG 行的必要条件，并给出了具体的实现路线"。
